# Write the Page

The page exists for its telos, in `PRODUCT.md`. Every word is written toward
the change it makes in a serious, skeptical reader, and is designed as it is
written.

## For each work

1. **Study the work whole.** Read all of it, not its README alone, until you
   can say why each of its rules exists and what breaks without it, without
   looking anything up.
2. **Catalog its value from every angle.** For each property: who gains
   (executive, owner, engineer, newcomer, auditor, an agent writing code, an
   agent acting), what it removes, what that costs today, and why it holds.
   Merge entries that are the same value; keep the honest count.
3. **Synthesize.** Ask which values make others possible, which exist only
   once agents are involved, and what becomes true only when all hold
   together. That is the gestalt.
4. **Decompose.** Break the gestalt into the few causes that produce it. Test
   them on values you did not build them from. If they are the work's own
   rules renamed, the synthesis did not happen.
5. **Demonstrate.** Start from facts every serious reader already accepts
   about their own organization, and reason forward until each value is
   forced. No example, demo or tagline carries any step.
6. **Teach.** Write so the reader reaches the conclusion themselves and could
   rebuild it without you. Then read it as a skeptic and rewrite until it
   passes.

## For the page

- Write from the through-line in `PRODUCT.md`: one idea at three levels,
  each sheet handing the reader to the next. Never three products for three
  problems.
- Find the fact every reader's seat shares and open on it. Let each seat
  find itself in passing; never address a role by name.
- Build to the turn: the one sentence each sheet exists for. It is the
  sheet's first paragraph of evidence and takes the turn role.
- Answer in the situation's own nouns, not the work's vocabulary.
- Say each thing once on the whole page.

## Write to the design

- Before a word: each element's job, place, type role and budget, from
  `DESIGN.md`. A headline is two lines; a contents entry, title or entry
  line is one; a sheet is about one desktop screen and its evidence no
  taller than its plate.
- If a sentence breaks its budget or wraps badly, rewrite the sentence,
  never the layout.
- Run `just measure`, look at every screen at 1440, 1280 and 390, and read
  the whole page as a stranger.

## Gotchas

- You will reach for a worked example because it is vivid. It replaces the
  reasoning; reason from what the work is instead.
- You will paste a line from the work's README or the book's storefront
  because it is already good. Every line is written for this page.
- You will answer a review note by adding a sentence. The page grows and
  gets worse. Rewrite the sheet whole.
- You will defend a line by where it came from. Only what it does to the
  reader counts.
- You will report the method's steps as the result. Only the page is the
  result.
